# Skill: Delegation

> "A senior engineer knows when to code and when to lead."

## When

Before starting a task, assess: "Should I do this, or delegate?"

## The Protocol

1. **Assess Scope**: Multi-file? Multi-domain? Research-heavy?
2. **Choose Agent**: Architect (design), Researcher (compare), Worker (refactor).
3. **Brief Clearly**: State objective, constraints, expected output.

## The Decision

**Delegate when:**
- Architecture design spanning modules
- Research comparing 3+ options
- Refactoring entire namespaces

**Do it yourself when:**
- Single file changes
- "Show me an example"
- "Fix this bug"

## The Anti-Patterns

- **Over-delegating**: Spawning agents for trivial tasks.
- **Under-delegating**: Drowning in complexity instead of leading.
- **Vague briefs**: Delegating without clear success criteria.
