# Context

What a summary loses, and what to read again before carrying on.

---

## A summary of a brief is not the brief

A long conversation runs out of room. It is compressed, and the work goes on from the summary.
**A brief compressed that way keeps its topic and loses its instructions.**

The rule is one line. **If the context was compacted while a brief was open, read the brief file
again first.**

It happened here. A 719-line brief became a paragraph, and that paragraph read like understanding
rather than loss. **Nothing feels absent, and that is what makes it dangerous.**

## The same holds for anything long

An issue's `## Done when` list, an RFC, a specification a run is building against. **Read the source,
not what a summary said about it.** Reading it twice costs a minute. Building against a paraphrase
costs the run.

## Where the long things live

| | |
|---|---|
| a brief | the operator's `briefs/` directory. The standing todo names which one an item uses |
| an item | `run.sh source read <n>`, which reads it live |
| a charter | `run.sh charter`, pinned at the run's base |

**A run already re-reads its own charter.** Nothing re-reads a brief, because nothing but a person
knows one exists.
